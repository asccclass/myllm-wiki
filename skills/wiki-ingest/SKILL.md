# 資料匯入（Ingest）

## 找到 Vault

1. 讀取工作階段內容中的 `myllm-wiki Vault:` 路徑。
2. 若沒有，讀取 `~/.claude/myllm-wiki/vault-path` 第一行。
3. 若仍沒有，確認目前目錄根部是否有 `AGENTS.md`（或 `CLAUDE.md`）與 `wiki/index.md`。
4. 都沒有時停止，建議使用 `wiki-init`。

以下 `<VAULT>` 代表絕對路徑；此 Skill 可在 Vault 外呼叫，因此所有路徑都必須使用絕對路徑。頁面格式與不可違反的規則依 `<VAULT>/AGENTS.md`（沒有時使用 `CLAUDE.md`）。

## 核心原則

讀取資料後，**擷取重點並整合至既有 Wiki**，不是只丟下一份摘要。單份資料可能影響 10–15 個頁面；建立索引與真正整合是不同的事。

## 不適用情況

- 詢問 Wiki 內容 → `wiki-query`
- 檢查 Wiki 健康狀態 → `wiki-lint`
- 記錄程式代理工作 → `wiki-log`

## 流程

### 1. 確認資料

確認資料位於 `<VAULT>/raw/`。若在外部，詢問使用者是否要移入；**不要自行移動**，因為 `raw/` 由使用者管理。

對 HWP、XLSX、PPTX、PDF 等二進位檔先擷取文字。含圖片的 Markdown 先讀文字，只在必要時查看個別圖片。

### 2. 先討論重點，不可跳過

讀完後向使用者提出 **3–5 個核心重點並取得方向**：要強調什麼、歸入哪個領域、要與既有內容如何連結。若使用者說「你自行處理」，才繼續進行。

### 3. 建立 source 頁面

在 `wiki/sources/` 為每份資料建立一頁，格式依 Vault Schema。務必記錄原始路徑，因為 `raw/` 不納入 Git，路徑是唯一連結。

### 4. 更新實體與概念頁面

資料中的人、組織、設備、系統、產品放入 `wiki/entities/`；技術、概念、方法論放入 `wiki/concepts/`。頁面不存在就建立；已存在就加入本次資料的出現紀錄並更新內容。若新資訊與既有敘述衝突，進入下一步。

### 5. 標記矛盾

若新資料與既有主張衝突，**雙方頁面都**設定 `status: contested`，並寫明衝突點及另一頁的連結。不要隱藏或靜默覆蓋；無法判定時明確標示未知。

### 6. 更新 index.md 與 log.md

在 `wiki/index.md` 的相應類別加入新頁面；在 `wiki/log.md` 底部追加：

```markdown
## [YYYY-MM-DD] ingest | <資料標題>

<說明新增內容及受影響頁面，約 2–3 行>
```

### 7. 回報結果

列出建立與更新的頁面，讓使用者能立即在 Obsidian 中確認。

## 快速參考

| 步驟 | 產出 |
|---|---|
| 1 | 確認資料位置與格式 |
| 2 | 討論重點並取得使用者同意 |
| 3 | `wiki/sources/<標題>.md` |
| 4 | 建立／更新 `wiki/entities/*`、`wiki/concepts/*` |
| 5 | 衝突時雙方標記 `contested` |
| 6 | 更新 `index.md`、`log.md` |
| 7 | 回報變更清單 |

## 常見錯誤

| 錯誤 | 結果 |
|---|---|
| 跳過重點討論直接寫入 | 十多個頁面的方向可能全部錯誤 |
| 只建立 source 頁面 | 變成摘要資料夾而非 Wiki |
| 不更新既有實體頁面 | 交叉引用無法累積 |
| 用新資訊覆蓋矛盾 | 過時資訊可能被誤認為事實 |
| 忘記更新 `index.md` | 查詢時找不到頁面 |
| 修改或移動 `raw/` 檔案 | 破壞真實來源 |

## 停止訊號

若想省略重點討論、稍後才建立實體頁面，或把矛盾直接當作新資訊，請停止並遵循上述流程。
